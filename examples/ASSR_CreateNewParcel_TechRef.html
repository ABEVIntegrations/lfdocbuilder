Trigger & Input Parameters

🔗
Sub-workflow — no schedule

This workflow has zero starting rules (schedules). It is designed to be called from a parent workflow or a Laserfiche Form via AllowProcessMessageStart="true". It will not run on its own.

Input Parameters

All six parameters are of type String, single-valued, and passed in from the calling workflow. They are all available as tokens throughout the workflow.

%(parcelID)
The Section-Block-Lot identifier for the parcel. Used in the folder name, metadata assignment, and email notification.
UUID: 3486331c-6682-4b38-91b8-2e8b160c070d · Style: InputFromWorkflow
%(streetNumber)
The building/house number. Combined with streetAddress to form the folder display name and StreetNumber metadata field.
UUID: 8698494a-ff9d-464a-8d5a-12433190ddaf
%(streetAddress)
The street name (without number). Used in the folder path hierarchy and the StreetName metadata field on the Properties template.
UUID: 7c56de20-5d96-4845-a2e0-f99a54bdf4c4
%(streetLetter)
Alphabetical grouping letter (A–Z). Determines which top-level letter subfolder under \Parcels\ the parcel lands in.
UUID: 78a257c9-1413-40f4-9747-3f7c69c68e52
%(emailAddress)
The recipient for completion/failure email notifications. Passed in by the calling workflow or form.
UUID: 77f89865-decc-4ba5-8994-dad2b4698ff8 · Note: referenced in parameter definition but the Email activities hard-code to email@email.com — see Email section.

⚠️
ParcelStatus is always set to "Active"

The workflow hardcodes ParcelStatus = Active regardless of the parcel's actual intended status. If you ever need to create a parcel that starts as Inactive, you would need to modify this workflow or update the field after creation.

Folder Structure

The workflow creates the following structure on every successful run. The path components are built from input parameters.

Path Formula

# Parent path (created if missing):
\Parcels\%(streetLetter)\%(streetAddress)\

# Root parcel folder name:
%(streetNumber) %(streetAddress) %(parcelID)

# Concrete example:
\Parcels\M\MAPLE AVE\100 MAPLE AVE 11.07.23\

Full Folder Tree

\Parcels\%(streetLetter)\%(streetAddress)\%(streetNumber) %(streetAddress) %(parcelID)\ ├── Assessor⊘ Read Only group: all rights DENIED ├── Buildinginherits parent permissions ├── Engineering⊘ Read Only group: all rights DENIED ├── Photos⊘ Read Only group: all rights DENIED ├── Planning⊘ Read Only group: all rights DENIED ├── Tax Billsinherits parent permissions └── Water⊘ Read Only group: all rights DENIED
ℹ️
Intermediate folders are created automatically

The Validation="CreateIt" flag means the letter folder (\Parcels\M\) and street name folder (MAPLE AVE\) are created automatically if they don't already exist. No pre-setup is required.

Permissions Model

The workflow sets permissions only on certain subfolders — those considered restricted to their respective departments. The ACE model used is an explicit deny entry that overrides inherited read access.

ACE Configuration (all Assign Rights activities)

Trustee:    "Read Only" (Laserfiche group)
Ace:        3  → Deny ACE
AddRights:  true  → add this ACE to the entry
Inherit:    true  → child entries also inherit this deny
Rights:     All 20 rights set to Access="false"
⚠️
Deny ACEs override Allow ACEs in Laserfiche

In Laserfiche's access model, an explicit Deny always wins over an Allow (even one inherited from a parent). If a user is a member of the "Read Only" group, they will be blocked from Assessor, Engineering, Photos, Planning, and Water subfolders even if they have other group memberships that grant access — unless those memberships have an explicit Allow that specifically overrides this deny, which is uncommon.

Troubleshooting

Common Issues

Received "Parcel NOT created because it already exists" — but I can't find it in the active parcels.
The duplicate check searches specifically in \Parcels\Z - INACTIVE BY SBL, not in the live \Parcels\ tree. The parcel exists in the inactive archive, not in active parcels.
  • Search in Laserfiche for the SBL under \Parcels\Z - INACTIVE BY SBL to find the existing record.
  • If the parcel should be activated, update its ParcelStatus field to Active and move it to the correct live location — do not run this workflow again, or you'll hit the same block.
  • If the inactive record is stale/incorrect, it may need to be deleted or reclassified before the new parcel can be created via this workflow.
The workflow completed but the parcel folder wasn't created — no email received either.
This most likely means the workflow failed silently before reaching the Create Parcel Folder activity. Check:
  • Workflow instance log in Laserfiche Administration Console → look for faulted activities or exceptions.
  • Input parameters — if %(parcelID), %(streetLetter), or %(streetAddress) were empty or null when passed in, folder creation may have succeeded with a blank path, then failed on the write.
  • Permissions on \Parcels\ — the workflow account needs Create permission on the target path. If the letter subfolder (e.g., \Parcels\M\) already exists but the workflow account lacks write access, the CreateIt validation will fail.
  • Duplicate folder name — if a folder with the exact same name already exists at that path, Laserfiche will error unless AutoRename is set (it isn't in this workflow). Check if an identically-named folder exists.
A user who should have access to a subfolder (e.g., Engineering) is being denied.
Five subfolders have an explicit DENY ACE for the "Read Only" group applied by this workflow. In Laserfiche, deny ACEs override allow ACEs.
  • If the user is a member of "Read Only," they will be blocked even if they are also a member of another group with explicit allow rights.
  • To grant access, you can either: (a) remove the user from the "Read Only" group, (b) remove the deny ACE from the specific subfolder in Laserfiche Security, or (c) modify the workflow to not add the deny ACE for that folder.
  • To check what ACEs are on a folder: right-click the folder in Laserfiche → Properties → Security. Look for any red X entries for "Read Only."
  • Note: Building and Tax Bills have no deny ACEs added by this workflow — they inherit from the parent parcel folder. If a user can't access those, check the parent folder's security settings instead.
No confirmation email was received after a parcel was successfully created.
Both email activities send to a hard-coded address (email@email.com), not to the %(emailAddress) input parameter.
  • If you expect email at a different address, the workflow needs to be updated — edit the "Email - Parcel Created" activity and change the To field to %(emailAddress).
  • Check that Laserfiche's SMTP server configuration is working by testing with another workflow that sends email.
  • Check the workflow instance log to confirm the Email activity ran without faulting.
Folders were created with blank or malformed names (e.g., a folder named just the SBL with no street info).
The folder name is assembled from three tokens: %(streetNumber) %(streetAddress) %(parcelID). If any of these were empty when passed in, the folder name will have blank segments or extra spaces.
  • The calling workflow or form is responsible for ensuring all parameters are non-empty before invoking this sub-workflow. Add validation at the source (the form or parent workflow) to require all fields.
  • If a malformed folder was already created, rename it manually in Laserfiche and update the StreetNumber and StreetName field values to match.
  • Similarly, %(streetLetter) controls the top-level routing path. An empty letter will create a folder directly under \Parcels\\ with a blank subfolder name — check \Parcels\ for any unnamed subfolders if this happens.
💡
Known items to review / improve

1. The "Parcel Not Created" email subject says "Parcel Created!" — this should be corrected to avoid confusion.
2. The %(emailAddress) parameter is declared but unused — both email activities should reference it for proper notification routing.
3. tokFolders and %(linkedParcelEntryID) are initialized/declared but not consumed — document their intended purpose or remove if no longer needed.
